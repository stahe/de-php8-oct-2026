    12. Das Datenbankmanagementsystem MySQL verwenden

    Wir schreiben nun PHP-Skripte, die eine MySQL-Datenbank verwenden:

    In der obigen Architektur kommuniziert das PHP-Skript [1] nicht direkt mit dem DBMS (Datenbankmanagementsystem) [3]. Es kommuniziert vielmehr mit einem Vermittler, dem sogenannten DBMS-Treiber [2]. PHP stellt für diese Treiber eine Standardschnittstelle bereit, die Schnittstelle [PDO] (PHP Data Objects). Diese Schnittstelle wird von verschiedenen, auf das jeweilige DBMS zugeschnittenen Treibern implementiert: ein Treiber für das DBMS MySQL, ein anderer für das DBMS PostgreSQL … Um zu einem anderen DBMS zu wechseln, wechselt man den Treiber:

    Der PDO-Treiber isoliert das PHP-Skript [1] vom DBMS [3, 6]. Da diese Treiber eine Standardschnittstelle implementieren, kann man erwarten, dass das PHP-Skript [1] beim Wechsel vom DBMS MySQL [3] zum DBMS PostgreSQL [6] unverändert bleibt. In der Realität gibt es dieses Ideal nicht. Um mit dem DBMS zu kommunizieren, sendet das PHP-Skript nämlich SQL-Befehle (Structured Query Language). Diese Sprache wird von allen DBMS implementiert, ist aber unvollständig. Folglich haben die DBMS ihr proprietäre Befehle hinzugefügt. Das ist eine erste Hauptursache für Inkompatibilitäten zwischen DBMS. Außerdem können sich die Datentypen, die in Datenbanken verwendet werden können, von einem DBMS zum anderen unterscheiden. PostgreSQL unterstützt zum Beispiel ein viel breiteres Spektrum an Datentypen als MySQL. Das ist eine zweite Ursache für Inkompatibilitäten. Eine weitere Ursache ist der Umgang mit automatischen Primärschlüsseln (die vom DBMS erzeugt werden): Praktisch jedes DBMS hat seine eigene Vorgehensweise. Usw. … Es gibt zahlreiche Ursachen für Inkompatibilitäten.

    Möchte man vermeiden, das PHP-Skript [1] beim Übergang von MySQL [3] zu PostgreSQL [6] neu schreiben zu müssen, muss man in der Regel eine neue Schicht zwischen das PHP-Skript [1] und die PDO-Treiber [2, 5] einfügen, eine Schicht, deren Aufgabe es ist, die Inkompatibilitäten zwischen den beiden DBMS aufzulösen. In den einfachen Fällen, denen wir begegnen werden, ist diese zusätzliche Schicht jedoch nicht nötig.

    Wir verwenden nun das DBMS MySQL. Dessen Version 8.4 ist in dem Paket [Laragon] enthalten, das wir zu Beginn dieses Kurses installiert haben.

    Wer mit den Konzepten von Datenbanken und der Sprache SQL noch nicht vertraut ist, kann das Dokument [http://sergetahe.com/cours-tutoriels-de-programmation/cours-tutoriel-sql-avec-le-sgbd-firebird/] heranziehen. Dieses Dokument verwendet das DBMS Firebird statt MySQL, behandelt aber die Grundlagen von Datenbanken und der Sprache SQL. Die Dokumentation zu MySQL 8.4 ist ebenfalls unter [https://dev.mysql.com/doc/refman/8.4/en/] verfügbar.

    12.1. Eine Datenbank erstellen

    Wir zeigen Ihnen nun, wie Sie mit dem Werkzeug [Laragon] eine Datenbank und einen MySQL-Benutzer erstellen.

    Nach dem Start wird [Laragon] über sein Hauptfenster und sein Menü verwaltet (Rechtsklick im Fenster oder auf sein Symbol in der Taskleiste):

    • Die Schaltfläche [Start All] startet den Webserver Apache und das DBMS MySQL. Das Fenster von [Laragon] zeigt dann an, dass beide aktiv sind, zusammen mit ihrem Listening-Port: 80 für Apache, 3306 für MySQL;
    • die Schaltfläche [Database] startet das Werkzeug [HeidiSQL], das in [Laragon] enthalten ist und mit dem sich MySQL-Datenbanken grafisch verwalten lassen. Sie können auch das Webwerkzeug [phpMyAdmin] installieren (Menü Tools / Quick Add), das dann über die URL [http://localhost/phpmyadmin] erreichbar ist;
    • die Schaltfläche [Terminal] öffnet ein Befehlsfenster, in dem die Werkzeuge von [Laragon] (PHP, Composer, MySQL usw.) direkt verwendet werden können.

    Der PHP-7-Kurs erstellte die Datenbank und ihren Benutzer mit der Maus in [phpMyAdmin]. Hier schreiben wir die entsprechenden SQL-Befehle lieber in eine Textdatei, ein sogenanntes SQL-Skript. Ein solches Skript lässt sich durchsehen, korrigieren, zusammen mit dem Anwendungscode aufbewahren und beliebig oft erneut ausführen, um die Datenbank genau so wiederherzustellen, wie sie war. Das Skript [dbpersons.sql] lautet wie folgt:

    -- Erstellung der Datenbank [dbpersons] und ihres Benutzers [admpersons]
-- auszuführen durch den Administrator [root] des MySQL-DBMS:
--   mysql -u root < dbpersons.sql

-- die Datenbank mit dem Zeichensatz [utf8mb4] (alle Unicode-Zeichen)
CREATE DATABASE IF NOT EXISTS dbpersons CHARACTER SET utf8mb4;

-- der Benutzer [admpersons] mit dem Passwort [nobody], der sich vom lokalen Rechner aus verbindet
CREATE USER IF NOT EXISTS 'admpersons'@'localhost' IDENTIFIED BY 'nobody';

-- er hat alle Rechte an der Datenbank [dbpersons] und nur an ihr
GRANT ALL PRIVILEGES ON dbpersons.* TO 'admpersons'@'localhost';

    Kommentare

    • Zeile 1: In SQL ist eine Zeile, die mit zwei Bindestrichen beginnt, ein Kommentar;
    • Zeile 6: Erstellt die Datenbank [dbpersons], falls sie noch nicht existiert. Darin legen wir eine Tabelle von Personen an. Der Zeichensatz [utf8mb4] ermöglicht es, alle Unicode-Zeichen zu speichern (Buchstaben mit Akzent, aber auch asiatische Schriftzeichen, Emojis usw.). Dies ist der Standardzeichensatz von MySQL 8. Der im PHP-7-Kurs verwendete Name [utf8] bezeichnet einen älteren, unvollständigen Zeichensatz von MySQL (höchstens drei Bytes pro Zeichen), der inzwischen veraltet ist;
    • Zeile 9: Anlegen des Benutzers [admpersons] mit dem Passwort [nobody]. Ein MySQL-Benutzer wird durch seinen Namen und den Rechner identifiziert, von dem aus er sich anmeldet – hier [localhost], der lokale Rechner. Das Passwort [nobody] ist sehr schwach (leicht zu erraten). In einer Produktionsumgebung sollten Sie ein sicheres Passwort wählen;
    • Zeile 12: Der Benutzer [admpersons] erhält alle Rechte an allen Tabellen ([dbpersons.*]) der Datenbank [dbpersons], aber keine Rechte an den anderen Datenbanken.

    Dieses Skript muss vom Administrator des DBMS ausgeführt werden. In der [Laragon]-Installation ist das der Benutzer [root], der kein Passwort hat. Öffnen Sie das [Laragon]-Terminal im Ordner [scripts-console/mysql] und führen Sie das Skript mit dem Kommandozeilen-Client [mysql] aus:

    1
    > mysql -u root < dbpersons.sql
    • Die Option [-u root] gibt den Benutzernamen an, mit dem die Anmeldung am DBMS erfolgt. Da [root] kein Passwort hat, muss keines angegeben werden (Option [-p]);
    • das Zeichen [<] leitet den Inhalt der Datei [dbpersons.sql] an die Eingabe des Clients [mysql] um, der die SQL-Befehle nacheinander ausführt. Wenn alles glattgeht, wird nichts angezeigt.

Überprüfen Sie die Rechte des Benutzers [admpersons], indem Sie sich als dieser Benutzer anmelden.     12.2. Verbindung zu einer MySQL-Datenbank herstellen

    Um eine Verbindung zu einem DBMS herzustellen, müssen Sie ein [PDO]-Objekt erzeugen. Dazu können Sie den Konstruktor der Klasse [PDO] oder ab PHP 8.4 deren statische Methode [connect] verwenden. Beide akzeptieren dieselben Parameter:

    1
2
    $connection = new PDO(string $dsn, ?string $username = null, ?string $password = null, ?array $options = null);
$connection = PDO::connect(string $dsn, ?string $username = null, ?string $password = null, ?array $options = null);

    Die Parameter haben folgende Bedeutung:

    Parameter
    Bedeutung
    [$dsn]
    (Data Source Name) eine Zeichenkette, die die Art des DBMS und seinen Ort im Netzwerk angibt. Die Zeichenkette ["mysql:host=localhost"] zeigt an, dass es sich um ein MySQL-DBMS handelt, das auf dem lokalen Rechner läuft. Diese Zeichenkette kann weitere, durch Semikolons getrennte Parameter enthalten, etwa den Port, auf dem das DBMS lauscht, den Namen der Datenbank, mit der Sie sich verbinden möchten, und den für die Kommunikation verwendeten Zeichensatz: ["mysql:host=localhost;port=3306;dbname=dbpersons;charset=utf8mb4"]
    [$username]
    der Benutzername des sich anmeldenden Benutzers
    [$password]
    sein Passwort
    [$options]
    ein Array mit Optionen für den DBMS-Treiber

    Nur der erste Parameter ist erforderlich. Das so erzeugte Objekt dient anschließend als Grundlage für alle Operationen, die auf der Datenbank ausgeführt werden, mit der Sie sich verbunden haben. Kann das Objekt nicht erzeugt werden, wird eine Ausnahme [PDOException] ausgelöst.

    <?php

// strikte Einhaltung der deklarierten Typen der Funktionsparameter und -ergebnisse
declare(strict_types=1);

// Verbindung zu einer lokalen MySQL-Datenbank
// die Identität des Benutzers ist (admpersons, nobody)
const ID = "admpersons";
const PWD = "nobody";
const HOST = "localhost";

try {
    // Verbindung
    $connection = PDO::connect("mysql:host=" . HOST, ID, PWD);
    print "Successful connection\n";
    // die Klasse des erhaltenen Objekts
    print "The connection is an object of type [" . $connection::class . "]\n";
    // Schließen der Verbindung
    $connection = null;
} catch (PDOException $ex) {
    print "Error: " . $ex->getMessage() . "\n";
    exit(1);
}

    Kommentare

    • Zeilen 8–10: die Verbindungsparameter;
    • Zeile 14: die Verbindung zum DBMS. Hier wird die Methode [connect] mit den folgenden Parametern verwendet:
      • eine Zeichenkette, die den Typ des DBMS und seinen Ort angibt. Die Zeichenkette ["mysql:host=localhost"] zeigt an, dass es sich um ein MySQL-DBMS handelt, das auf dem lokalen Rechner läuft. Der Port wurde nicht angegeben; es wird daher standardmäßig Port 3306 verwendet. Auch der Datenbankname ist nicht angegeben. Es wird dann eine Verbindung zum MySQL-DBMS aufgebaut, und eine bestimmte Datenbank kann später ausgewählt werden;
      • eine Benutzerkennung;
      • sein Passwort;
    • Zeile 17: [$connection::class] ist der Klassenname des Objekts [$connection]. Ab PHP 8.4 hat jeder PDO-Treiber eine eigene, von der Klasse [PDO] abgeleitete Klasse: [Pdo\Mysql] für MySQL, [Pdo\Pgsql] für PostgreSQL, [Pdo\Sqlite] für SQLite. Die Methode [PDO::connect] erzeugt ein Objekt der Klasse, die dem DSN entspricht. Mit [new PDO(...)] erhielten wir ein Objekt der Klasse [PDO] selbst, das genauso funktioniert, aber keinen Zugriff auf treiberspezifische Methoden bietet. Da wir nur die allen Treibern gemeinsamen Methoden verwenden, sind beide Schreibweisen zulässig;
    • Zeile 19: Die Verbindung wird geschlossen, indem die letzte Referenz auf das ursprünglich erzeugte PDO-Objekt entfernt wird. Das geschieht automatisch am Ende des Skripts;
    • Zeile 20: Die Verbindung zu einem DBMS kann fehlschlagen. In diesem Fall wird eine Ausnahme [PDOException] ausgelöst. Diese Ausnahme ist von der PHP-Ausnahme [RuntimeException] abgeleitet;
    • Zeile 21: Die Fehlermeldung der Ausnahme wird angezeigt;
    • Zeile 22: Das Skript wird mit einem Exit-Code ungleich null beendet, der einem aufrufenden Programm den Fehlschlag signalisiert.

    <?php

// strikte Einhaltung der deklarierten Typen der Funktionsparameter und -ergebnisse
declare(strict_types=1);

// Identität der Datenbank
const DSN = "mysql:host=localhost;dbname=dbpersons;charset=utf8mb4";
// Zugangsdaten des Benutzers
const ID = "admpersons";
const PWD = "nobody";

try {
    // Verbindung zur MySQL-Datenbank
    $connection = PDO::connect(DSN, ID, PWD);
    // Löschen der Tabelle [persons], falls sie existiert
    $sql = "drop table if exists persons";
    $connection->exec($sql);
    // Erstellen der Tabelle [persons]
    $sql = "create table persons (first_name varchar(30) not null, last_name varchar(30) not null, "
        . "age integer not null, primary key(last_name, first_name))";
    $connection->exec($sql);
    print "The [persons] table has been created\n";
} catch (PDOException $ex) {
    // Fehleranzeige
    print "Error: " . $ex->getMessage() . "\n";
} finally {
    // wir trennen die Verbindung, falls nötig
    $connection = null;
}
// Ende
print "Done\n";

    Kommentare

    • Zeile 7: Dieses Mal verweist der DSN auf die Datenbank [dbpersons] ([dbname=dbpersons]). Der Parameter [charset=utf8mb4] teilt dem DBMS mit, dass die mit ihm ausgetauschten Zeichenketten in UTF-8 kodiert sind, der in unseren (PHP-)Skripten verwendeten Kodierung. So ist sichergestellt, dass Umlaute und andere Sonderzeichen korrekt in der Datenbank gespeichert und korrekt wieder ausgelesen werden;
    • Zeile 14: Verbindung zur Datenbank herstellen. Das ist immer der erste Schritt. Das Ergebnis der Verbindung ist ein [PDO]-Objekt, über das die Datenbankoperationen ausgeführt werden;
    • Zeile 16: Der SQL-Befehl [drop table] löscht die Tabelle [persons] aus der Datenbank [dbpersons]. Die Klausel [if exists] verhindert einen Fehler, wenn die Tabelle [persons] nicht existiert;
    • Zeile 17: Ausführung des vorherigen SQL-Befehls auf der Datenbank [dbpersons] mit der Methode [PDO::exec]. Diese Ausführung kann eine [PDOException] auslösen, die von der Klausel [catch] abgefangen wird;
    • Zeilen 19–20: Dieser SQL-Befehl erstellt eine Tabelle namens [persons]. Eine Tabelle besteht aus Zeilen und Spalten. Die Spalten bilden die sogenannte Tabellenstruktur. Die Zeilen bilden den Inhalt der Tabelle. Eine Datenbank kann eine oder mehrere Tabellen enthalten. Die Tabelle [persons] hat hier drei Spalten:
      • first_name: der Vorname einer Person als Zeichenkette mit höchstens 30 Zeichen;
      • last_name: der Nachname derselben Person als Zeichenkette mit höchstens 30 Zeichen;
      • age: das Alter der Person als ganze Zahl;
      • Das Attribut [not null] einer Spalte verlangt, dass die Spalte einen Wert hat. Wird keiner angegeben, führt das zu einem Fehler [PDOException];
      • [primary key(last_name, first_name)] definiert einen Primärschlüssel für die Tabelle [persons]. Ein Primärschlüssel hat für jede Zeile der Tabelle einen eindeutigen Wert. Hier entsteht der Primärschlüssel durch Verkettung der Spalten [last_name] und [first_name] der Zeile. Diese Einschränkung stellt sicher, dass die Tabelle nicht zwei Personen mit demselben Vor- und Nachnamen enthalten kann, also zwei Personen mit demselben vollständigen Namen. Das Anlegen einer Person mit demselben Namen wie eine bereits vorhandene löst eine [PDOException] aus;
    • Zeilen 23–25: Tritt eine [PDOException] auf, wird die zugehörige Fehlermeldung angezeigt;
    • Zeilen 26–28: Die Klausel [finally] wird in jedem Fall ausgeführt, ob eine Ausnahme auftritt oder nicht, um die Verbindung zur Datenbank zu schließen.

    Im Fehlerfall kann eine mit einem [PDO]-Objekt ausgeführte SQL-Operation entweder einen bestimmten Wert zurückgeben (oft den booleschen Wert [false]), ohne etwas zu melden, oder eine Ausnahme auslösen. Dieses Verhalten wird durch das Attribut [PDO::ATTR_ERRMODE] der Verbindung gesteuert. In PHP 7 war der Standardmodus der erste: Fehler wurden stillschweigend ignoriert, und das Vorgehen unter PHP 7 forderte den zweiten Modus mit der folgenden Anweisung an:

    1
    $connection->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);

    Seit PHP 8.0 ist der Ausnahmemodus der Standard: Jeder DBMS-Fehler löst eine [PDOException] aus. Diese Anweisung ist daher nicht mehr nötig, und wir verwenden sie nicht mehr. Deshalb haben wir auch [drop table if exists] geschrieben: In PHP 7 schlug der Befehl [drop table persons] für eine nicht vorhandene Tabelle stillschweigend fehl; in PHP 8 würde er eine Ausnahme auslösen.

function executeCommands(PDO $connection, string $sqlFileName, bool $tracking = false, bool $stop = true): array
{
    // verwendet die Verbindung $connection
    // führt die SQL-Befehle aus, die in der Textdatei $sqlFileName enthalten sind
    // diese Datei enthält auszuführende SQL-Befehle, einen pro Zeile
    // wenn $tracking true ist, wird jede Ausführung einer SQL-Anweisung mit Erfolg oder Misserfolg angezeigt
    // wenn $stop true ist, hält die Funktion beim 1. aufgetretenen Fehler an, andernfalls führt sie alle SQL-Befehle aus
    // die Funktion gibt das Array der Fehlermeldungen zurück (leer, wenn es keinen Fehler gab)

        ? file($sqlFileName, FILE_IGNORE_NEW_LINES | FILE_SKIP_EMPTY_LINES)
        : false;
    // Fehler?

        return ["The file [$sqlFileName] does not exist or could not be read"];
    }
    // wir führen die Abfragen nacheinander aus - zu Beginn keine Fehler
    $errors = [];
    foreach ($queries as $query) {
        // wir entfernen die Leerzeichen am Anfang und Ende der Zeile

        // leere Abfrage?

            // wir gehen zur nächsten Abfrage über
            continue;

            // Ausführung der Abfrage - bei einem Fehler wird eine Exception geworfen

// ---------------------------------------------------------------------------------
function displayInfo(string $command, PDOStatement|int $result): void
{
    // zeigt das Ergebnis $result einer SQL-Abfrage an
    if ($result instanceof PDOStatement) {
        // Fall des select: wir zeigen die Spaltennamen an
        $columns = [];
        for ($i = 0; $i < $result->columnCount(); $i++) {
            $columns[] = $result->getColumnMeta($i)["name"];
        }
        $title = implode(",", $columns);
        print "$title\n";
        // Trennzeile von gleicher Länge wie der Titel
        print str_repeat("-", mb_strlen($title)) . "\n";
        // die Zeilen des Ergebnisses: jede ist ein Array der Spaltenwerte
        foreach ($result as $row) {
            print implode(",", $row) . "\n";
        }
        return;
    }
    // Fall der Anweisungen insert, update, delete: $result ist die Anzahl der geänderten Zeilen
    if (in_array($command, ["insert", "update", "delete"], true)) {
        print " $result row(s) has (have) been modified\n";
    }
}

    • eine vorbereitete Anweisung;
    • n Ausführungen der vorbereiteten Anweisung;

    ist hinsichtlich der Ausführungszeit effizienter als die Ausführung von n verschiedenen SQL-Anweisungen. Beim SQL-Befehl [select] werden die Ergebniszeilen nach der Ausführung mit [PDOStatement::execute] mit den Methoden [PDOStatement::fetch] oder [PDOStatement::fetchAll] abgerufen.

    12.7. Transaktionen verwenden

    Eine Transaktion ermöglicht es, eine Folge von SQL-Befehlen zu einer einzigen Ausführungseinheit zusammenzufassen: Entweder gelingen alle Befehle, oder einer davon schlägt fehl, und dann werden alle vorhergehenden SQL-Befehle rückgängig gemacht. Mit anderen Worten: Wenn Sie SQL-Befehle in einer Transaktion ausführen, befindet sich die Datenbank nach Abschluss der Transaktion in einem stabilen Zustand:

    • entweder in einem neuen Zustand, der durch die erfolgreiche Ausführung aller SQL-Befehle der Transaktion entstanden ist;
    • oder in dem Zustand, in dem sie sich vor Beginn der Ausführung der Transaktion befand.

    function executeCommands(PDO $connection, string $sqlFileName, bool $tracking = false): array
{
    // verwendet die Verbindung $connection
    // führt die SQL-Befehle aus, die in der Textdatei $sqlFileName enthalten sind
    // diese Datei enthält auszuführende SQL-Befehle, einen pro Zeile
    // wenn $tracking true ist, wird jede Ausführung einer SQL-Anweisung mit Erfolg oder Misserfolg angezeigt
    // die SQL-Befehle werden in einer Transaktion ausgeführt: schlägt einer davon fehl, wird die Transaktion zurückgerollt
    // und die Datenbank befindet sich wieder in dem Zustand vor der Transaktion
    // die Funktion gibt das Array der Fehlermeldungen zurück (leer, wenn es keinen Fehler gab)

    // wir legen die Zeilen der Datei in einem Array ab, ohne Zeilenende-Zeichen und ohne leere Zeilen
    $queries = is_readable($sqlFileName)
        ? file($sqlFileName, FILE_IGNORE_NEW_LINES | FILE_SKIP_EMPTY_LINES)
        : false;
    // Fehler?
    if ($queries === false) {
        return ["The file [$sqlFileName] does not exist or could not be read"];
    }
    // die Abfragen werden in einer Transaktion ausgeführt
    $connection->beginTransaction();
    // wir führen die Abfragen nacheinander aus - zu Beginn keine Fehler
    $errors = [];
    foreach ($queries as $query) {
        // wir entfernen die Leerzeichen am Anfang und Ende der Zeile
        $query = trim($query);
        // leere Abfrage?
        if ($query === "") {
            // wir gehen zur nächsten Abfrage über
            continue;
        }
        // der Name des SQL-Befehls: das erste Wort der Abfrage, in Kleinbuchstaben
        $command = strtolower(explode(" ", $query, 2)[0]);
        try {
            // Ausführung der Abfrage - bei einem Fehler wird eine Exception geworfen
            // eine SELECT-Anweisung liefert Zeilen, die anderen Anweisungen eine Anzahl geänderter Zeilen
            $result = $command === "select"
                ? $connection->query($query, PDO::FETCH_NUM)
                : $connection->exec($query);
            // Anzeige auf dem Bildschirm oder nicht?
            if ($tracking) {
                print "[$query]: Successful execution\n";
            }
            // wir zeigen das Ergebnis der Ausführung an
            displayInfo($command, $result);
        } catch (PDOException $ex) {
            // ein Fehler ist aufgetreten
            addError($errors, $query, $ex->getMessage(), $tracking);
            // wir halten beim 1. Fehler an
            break;
        }
    }
    // Ende der Transaktion
    if ($errors === []) {
        // es gab keine Fehler: wir bestätigen die Transaktion per Commit
        $connection->commit();
    } else {
        // es gab einen Fehler: wir rollen die Transaktion zurück
        $connection->rollBack();
        // Hinzufügen eines Fehlers
        addError($errors, "", "Transaction rolled back", $tracking);
    }
    // Ergebnis
    return $errors;
}

    Zusammenfassung:

    • Eine Transaktion beginnt mit der Methode [PDO::beginTransaction];
    • sie wird mit der Methode [PDO::commit] erfolgreich abgeschlossen;
    • sie wird bei einem Fehlschlag mit der Methode [PDO::rollBack] beendet;
    • die Methode [PDO::inTransaction] gibt an, ob eine Transaktion läuft.

    Bei der Arbeit mit einer Datenbank empfiehlt es sich, jede SQL-Operation in eine Transaktion zu packen, um sie von anderen Benutzern der Datenbank zu isolieren (auch das ist einer ihrer Zwecke). Eine Transaktion sollte so kurz wie möglich sein. Beenden Sie sie daher unbedingt je nach Fall mit einem [commit] oder einem [rollBack], . Beachten Sie schließlich: Bei MySQL lassen sich Befehle, die die Struktur der Datenbank ändern ([create table], [drop table] usw.), nicht zurückrollen. Sie bestätigen die aktuelle Transaktion implizit. Deshalb enthält die Datei [sql2.txt] nur Befehle vom Typ [select], [insert], [update] und [delete] .
