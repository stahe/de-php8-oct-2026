    24. Praktische Übung – Version 13

    Version 13 bringt nur wenige Änderungen: Sie sichert den Zugriff auf die Dateien der Anwendung. Neue Funktionen kommen nicht hinzu: Die Aktionen, die JSON-, XML- und HTML-Antworten sowie die Views sind dieselben wie in Version 12. Geändert haben sich die Dateistruktur auf der Festplatte und die Konfiguration des Servers [Apache].

    24.1. Das Problem

    Im Kurs PHP 7 konnten Sie die URL der Konfigurationsdatei von Version 12 anfordern, und der Browser zeigte sie an. Diese Datei [config.json] enthält jedoch sensible Informationen, etwa die Zugangsdaten der Benutzer, die die Anwendung verwenden dürfen. Sie darf für Benutzer nicht zugänglich sein.

    In unserer Version 12 ist diese Datei bereits geschützt: Sie befindet sich im Ordner [Data], dem die Datei [.htaccess] – eingeführt mit Version 8 – den Zugriff verwehrt (Direktive [Require all denied]). Dieser Schutz wird jedoch von Fall zu Fall angewendet: Wir sperren nur, was wir gezielt gesperrt haben, und alles andere wird ausgeliefert. Dabei gibt es noch vieles, was nicht angezeigt werden sollte. So kann der Browser beispielsweise direkt eine View anfordern, ohne den Hauptcontroller zu durchlaufen:

    24.4. Die Datei [.htaccess] der Anwendung

    Mit [Laragon] ist das Dokumentenstammverzeichnis des Servers [Apache] (Direktive [DocumentRoot]) der Ordner [www]. Daher ist alles unterhalb von [www] über eine URL erreichbar, insbesondere der gesamte Ordner [version-13]. Um den Zugriff auf alles zu beschränken, was nicht im Ordner [public] liegt, verwenden wir eine einzige Datei [.htaccess] im Stammordner der Anwendung, im Ordner [version-13]. Beachten Sie, dass die Direktiven einer Datei [.htaccess] für den Ordner gelten, der sie enthält, und für alle seine Unterordner. [Laragon] konfiguriert [Apache] so, dass diese Dateien gelesen werden (Direktive [AllowOverride All]):

    # Version 13: nur der Ordner [public] der Anwendung ist über das Web erreichbar
# (Apache 2.4 - das Modul [mod_rewrite] muss aktiv sein, was bei Laragon der Fall ist)

# keine Auflistung des Inhalts der Ordner
Options -Indexes

# URL-Rewriting: die Muster werden mit dem URL-Pfad relativ zum Ordner [version-13] verglichen
RewriteEngine On
# die URL des Ordners der Anwendung [.../version-13/] wird auf den Ordner [public] umgeleitet
# %1: der Pfad der angeforderten URL ohne das abschließende /, erfasst durch die Bedingung [RewriteCond]
RewriteCond %{REQUEST_URI} ^(.*)/$
RewriteRule ^$ %1/public/ [R=302,L]
# jede andere URL, die weder den Ordner [public] noch eine seiner Dateien bezeichnet, wird abgelehnt (403 Forbidden)
RewriteRule !^public(/|$) - [F]

    Kommentare

    • Zeile 5: Wenn eine URL einen Ordner angibt, der kein Standarddokument ([index.php], [index.html]) besitzt, kann [Apache] die Liste der Dateien im Ordner anzeigen. Die Direktive [Options -Indexes] verhindert das;
    • Zeile 8: Wir verwenden das Modul [mod_rewrite] von [Apache], das Modul zum Umschreiben von URLs, das in [Laragon] standardmäßig aktiviert ist. Eine Regel [RewriteRule] hat die Form [RewriteRule pattern substitution [options]]. In einer Datei [.htaccess] wird das Muster – ein regulärer Ausdruck – mit dem Pfad der angeforderten URL verglichen, und zwar relativ zum Verzeichnis der Datei [.htaccess]. Für die URL [http://localhost/php8-oct-2026/scripts-web/tax/version-13/Config/config.json] lautet dieser Pfad [Config/config.json];
    • Zeilen 11–12: Die erste Regel verarbeitet die URL des Anwendungsordners [.../version-13/], dessen relativer Pfad leer ist (Muster: [^$]). Sie leitet den Browser (Option [R=302]) auf den Ordner [public] um und beendet die Verarbeitung der Regeln (Option [L], für „last“). Die Substitution muss ein vollständiger URL-Pfad sein: Er wird aus der Variablen [REQUEST_URI] von [Apache] gewonnen, dem Pfad der angeforderten URL [/php8-oct-2026/scripts-web/tax/version-13/]. Die der Regel vorangehende Bedingung [RewriteCond] vergleicht diese Variable mit dem regulären Ausdruck [^(.*)/$]: Der Teil in Klammern – der Pfad ohne den abschließenden Schrägstrich – steht dann in der Regel unter dem Namen [%1] zur Verfügung. So hängt die Datei [.htaccess] nicht vom Speicherort der Anwendung im Ordner [www] ab;
    • Zeile 14: Die zweite Regel gilt für jede URL, deren relativer Pfad nicht mit [public/] beginnt und nicht genau [public] lautet: Das bedeutet das [!] vor dem Muster. Die Substitution [-] bedeutet „keine Substitution“, und die Option [F] (für „forbidden“) veranlasst [Apache], mit dem Code [403 Forbidden] zu antworten. Die URL [.../version-13/public] ohne abschließenden Schrägstrich muss erlaubt bleiben: [Apache] (Modul [mod_dir]) antwortet darauf mit einer Weiterleitung auf [.../version-13/public/].

    Diese Datei blockiert auch den Zugriff auf sich selbst: Sie befindet sich nicht im Ordner [public]. Da der Pfad einer URL von [Apache] normalisiert wird, bevor die Regeln angewendet werden, wird auch eine URL wie [.../version-13/public/../Config/config.json] abgelehnt.

    Der Kurs PHP 7 legte in jedem der zu schützenden Ordner eine Datei [.htaccess] mit den beiden Zeilen [order deny,allow] und [deny from all] ab. Das ist die Syntax von [Apache] 2.2. [Apache] 2.4 akzeptiert sie nur noch über das Kompatibilitätsmodul [mod_access_compat], dessen Abschaffung geplant ist. Die Syntax für [Apache] 2.4 lautet [Require all denied], die wir seit Version 8 verwenden.

    Wenn Sie das Modul [mod_rewrite] nicht verwenden möchten, gibt es eine mögliche Alternative mit zwei Dateien [.htaccess] und der Syntax [Require]:

    • im Ordner [version-13] eine Datei namens [.htaccess] mit nur der Zeile [Require all denied]: Alles ist verboten;
    • im Ordner [public] eine Datei namens [.htaccess] mit nur der Zeile [Require all granted]: Die Zugriffseinstellungen eines Unterordners überschreiben die des übergeordneten Ordners, und der gesamte Inhalt von [public] ist erlaubt.

    Diese Variante funktioniert ebenfalls, aber der Zugriff auf die URL [.../version-13/] wird dann verweigert, statt auf den Ordner [public] weitergeleitet zu werden.

    24.5. In der Produktion: Das Dokumentenstammverzeichnis ist der Ordner [public]

    Die Datei [.htaccess] ist eine Lösung, die auf [Laragon] zugeschnitten ist, wo ein einziger Ordner, [www], mehrere Anwendungen enthält. Auf einem Produktionsserver ist das Vorgehen anders: Der Ordner [public] wird zum Dokumentenstammverzeichnis der Website gemacht. Der Rest der Anwendung liegt dann außerhalb der Verzeichnisstruktur der Website: Keine URL kann darauf zugreifen, und es sind keine Regeln nötig. Diese Organisation wird von den PHP-Frameworks empfohlen.

    Mit [Apache] definieren Sie dazu einen virtuellen Host, d. h. eine zusätzliche Website, die vom selben Server [Apache] bereitgestellt wird. Die Datei [Config/vhost-tax-v13.conf] liefert ein Beispiel:

Listen 8013
<VirtualHost *:8013>
    # das Document Root: nur der Inhalt von [public] ist über das Web erreichbar
    DocumentRoot "C:/laragon/www/php8-oct-2026/scripts-web/tax/version-13/public"
    <Directory "C:/laragon/www/php8-oct-2026/scripts-web/tax/version-13/public">
        # keine zu lesende [.htaccess]-Datei: die Konfiguration steht hier
        AllowOverride None
        Options -Indexes
        Require all granted
    </Directory>
</VirtualHost>
    • Zeile 4: [Apache] lauscht auch auf Port 8013. Ein virtueller Host lässt sich von anderen durch seinen Port unterscheiden, wie hier gezeigt, oder durch seinen Namen ([tax.test], zum Beispiel). Die Verwendung des Ports erspart es, einen neuen Hostnamen zu deklarieren;
    • Zeilen 5–14: Die Konfiguration des virtuellen Hosts, der auf Anfragen an Port 8013 antwortet;
    • Zeile 7: Das Dokumentenstammverzeichnis dieser Website ist der Ordner [public] der Version 13. Die URL [http://localhost:8013/main.php] bezeichnet daher die Datei [public/main.php];
    • Zeilen 8–13: Zugriffsrechte für den Ordner [public]. [AllowOverride None] teilt [Apache] mit, dass er nicht nach Dateien [.htaccess] suchen muss: Die gesamte Konfiguration steht hier, was auch schneller ist.

    Legen Sie in [Laragon] eine solche Datei – mit angepassten Pfaden zum Installationsordner von [Laragon] – im Ordner [<laragon>/etc/apache2/sites-enabled] ab und starten Sie dann [Apache] im Fenster von [Laragon] neu (klicken Sie auf die Schaltfläche [Stop], dann auf die Schaltfläche [Start All] ). Das ist der Vorteil der neuen Verzeichnisstruktur: Öffentliche Inhalte sind in einem einzigen Ordner gebündelt, und alles andere ist standardmäßig geschützt.
