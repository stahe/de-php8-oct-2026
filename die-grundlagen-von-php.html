    Kommentare:

    • Zeile 4: weist PHP an, die deklarierten Typen der Parameter und Funktionsrückgaben strikt zu prüfen. Wir kommen im Abschnitt über Typänderungen darauf zurück. Merken Sie sich vorerst, dass alle Skripte dieses Kurses so beginnen;
    • Zeile 8: In PHP werden Variablen nicht deklariert. Sie haben einen dynamischen Typ, der sich im Lauf der Zeit ändern kann. [$name] steht für die Variable mit dem Bezeichner [name];
    • Zeile 10: Zur Ausgabe auf dem Bildschirm können Sie die Anweisung [print] oder die Anweisung [echo] verwenden;
    • Zeile 12: Die Schreibweise [[...]] dient zur Definition eines Arrays. Die Schreibweise [$array[$i]] steht für das Element Nr. [$i] des Arrays [$array], wobei das erste Element die Nummer 0 trägt. Die ältere Schreibweise [array("one", "two", 3, 4)] wird weiterhin akzeptiert, aber wir verwenden sie nicht;
    • Zeile 14: Die Funktion [count($array)] liefert die Anzahl der Elemente des Arrays [$array] zurück;
    • Zeilen 16–18: eine Schleife. Da diese Schleife nur eine Anweisung enthält, sind die geschweiften Klammern optional. Im weiteren Verlauf dieses Dokuments verwenden wir stets geschweifte Klammern, unabhängig von der Anzahl der Anweisungen;
    • Zeile 17: Zeichenketten werden in doppelte Anführungszeichen " oder einfache Anführungszeichen ' gesetzt. In doppelten Anführungszeichen werden die Variablen [$variable] ausgewertet (man spricht auch von „Interpolation“), in einfachen nicht;
    • Zeile 20: Sie können die Elemente eines Arrays in einer einzigen Operation mehreren Variablen zuweisen. Hier gilt [$string1="string1"] und [$string2="string2"]. Diese Syntax, Destrukturierung genannt, ersetzt die Funktion [list] älterer PHP-Versionen: [list($string1, $string2) = ...] wird weiterhin akzeptiert;
    • Zeile 22: Der Operator . (Punkt) ist der Operator zur Verkettung von Zeichenketten;
    • Zeilen 91–95: Das Schlüsselwort [function] definiert eine Funktion. Eine Funktion kann an beliebiger Stelle im Skript definiert werden, auch nach ihrer Verwendung. Hier bedeutet [string $string], dass der Parameter [$string] eine Zeichenkette sein muss, und [: void] zeigt an, dass die Funktion kein Ergebnis zurückgibt. Diese Typdeklarationen sind in PHP optional, wir verwenden sie aber durchgängig: Sie dokumentieren den Code und ermöglichen es PHP (und dem Editor), Fehler zu erkennen;
    • Zeile 98: Der Typ [mixed] (PHP 8.0) bedeutet „beliebiger Typ“. Der Parameter [$variable] kann eine Ganzzahl, eine Zeichenkette, ein Array usw. aufnehmen;
    • Zeile 101: Die vordefinierte Funktion [gettype($variable)] liefert eine Zeichenkette zurück, die den Typ von [$variable] darstellt. Die Ergebnisse zeigen, dass sich dieser Typ im Lauf der Zeit ändern kann: [$n] ist zuerst eine Ganzzahl und dann eine Zeichenkette;
    • Zeile 105: Eine Funktion gibt ein Ergebnis mit der Anweisung [return] zurück. Der Typ dieses Ergebnisses wird hinter den Klammern deklariert: [: int]. Der aufrufende Code kann die Ergebnisse einer Funktion ignorieren oder abrufen;
    • Zeile 112: Eine Funktion kann mehrere Werte zurückgeben, indem sie diese in einem Array zusammenfasst;
    • Zeilen 53–62: Der Operator [===] führt einen strikten Vergleich zweier Elemente durch: Sie müssen denselben Typ und denselben Wert haben, um gleich zu sein. Der Operator [] ist weniger streng: Zwei Elemente können gleich sein, ohne denselben Typ zu haben. In diesem Fall erfolgt der Vergleich, nachdem beide Elemente in denselben Typ umgewandelt wurden. Man „übersieht“ diese impliziten Umwandlungen leicht und gelangt so zu unerwarteten Ergebnissen, etwa wenn sich eine Bedingung als wahr erweist, obwohl man sie für falsch hielt. Um diese Falle zu vermeiden, verwenden wir durchgängig den Vergleichsoperator [=] (und seine Negation [!==]);
    • Zeilen 64–68: ein Beispiel für diese impliziten Umwandlungen. In PHP 7 wurde die Zeichenkette „abc“ in die Zahl 0 umgewandelt, und der Ausdruck [0 == "abc"] war wahr! Seit PHP 8.0 wird beim Vergleich einer Zahl mit einer Zeichenkette, die keine Zahl darstellt, die Zahl in eine Zeichenkette umgewandelt, und der Ausdruck ist falsch. Das Verhalten von [] hat sich also von einer Version zur anderen geändert: ein Grund mehr, [=] den Vorzug zu geben;
    • Zeile 72: Die Funktion [is_int] liefert [true] zurück, wenn ihr Parameter eine Ganzzahl ist. Entsprechend gibt es [is_string], [is_float], [is_bool], [is_array] … Der Operator [&&] ist das logische UND. Sie können auch die logischen Operatoren [||] (ODER) und [!] (NICHT) verwenden. PHP unterstützt außerdem die Schlüsselwörter [and] und [or], doch ihre im Vergleich zur Zuweisung niedrigere Priorität kann zu unerwarteten Ergebnissen führen: Wir verwenden sie nicht;
    • Zeile 80: eine [while]-Schleife. Sie endet, sobald die Bedingung falsch ist – hier, sobald das Array durchlaufen ist oder ein negatives oder null betragendes Element gefunden wird;
    • Zeile 88: Die Anweisung [exit] beendet die Ausführung des Skripts. Die folgenden Funktionen werden an dieser Stelle nicht ausgeführt, sind aber dem gesamten Skript bekannt.

    Beachten Sie, dass das Skript nicht mit dem schließenden PHP-Tag [?>] endet. Es ist nicht zwingend erforderlich. Außerdem kann es in einem Web-Kontext Probleme verursachen, wenn ihm Leerzeichen oder Zeilenumbrüche folgen, die schwer zu erkennen sind, weil sie in einem Texteditor nicht sichtbar sind. Die Empfehlung [PSR-12] legt tatsächlich fest, dass es in Dateien, die nur PHP enthalten, wegzulassen ist. Daher lassen wir es im weiteren Verlauf dieses Dokuments systematisch weg.

    Hinweis: In diesem Dokument verwenden wir das Schlüsselwort [print] , um Text auf der Konsole auszugeben. Dasselbe lässt sich auch mit dem Schlüsselwort [echo] erreichen. Zwischen diesen beiden Schlüsselwörtern gibt es feine Unterschiede, die im Rahmen dieses Dokuments jedoch keine Rolle spielen. Wenn Sie also lieber [echo] verwenden, nur zu.

    3.3.2. Verwendung von VS Code

    Um mit den Kursskripten zu arbeiten, öffnen Sie den Ordner [php8-oct-2026] in [VS Code] (Menü [File > Open Folder]). Der Dateibaum erscheint im Explorer am linken Fensterrand. So führen Sie ein Skript aus:

    • Öffnen Sie ein integriertes Terminal (Menü [Terminal > New Terminal]). Es öffnet sich im Ordner [php8-oct-2026];
    • wechseln Sie in den Ordner des Skripts: [cd scripts-console/basics];
    • führen Sie das Skript aus: [php basics-01.php]. Die Ergebnisse werden im Terminal angezeigt. Alternativ können Sie im Datei-Explorer mit der rechten Maustaste auf den Ordner [basics] klicken und [Open in Integrated Terminal] wählen.

    Wird der Befehl [php] nicht erkannt, befindet sich der PHP-Ordner nicht im Windows-PATH: [Laragon] trägt ihn dort ein, wenn Sie die entsprechende Option in seinem Menü [Tools > Path] aktivieren. Der Befehl [php -v] sollte Version 8.5 anzeigen.

    Die Erweiterung [PHP Intelephense] analysiert den Code während der Eingabe und markiert Probleme durch eine Wellenlinie unter dem fehlerhaften Code. Fahren Sie mit der Maus über diese Linie, wird die Meldung angezeigt. Alle Probleme der Datei werden im Bereich [Problems] (Menü [View > Problems]) aufgelistet. Zu den nützlichen Warnungen zählen:

    • [Undefined variable]: Eine Variable wird verwendet, ohne initialisiert worden zu sein. Oft ist dies ein Tippfehler im Variablennamen;
    • [Undefined function]: Es wird eine Funktion aufgerufen, die nicht existiert; auch hier handelt es sich oft um einen Tippfehler;
    • [Expected type 'int'. Found 'string'.]: Ein aktueller Parameter hat nicht den von der Funktion deklarierten Typ. Dies ist einer der großen Vorteile von Typdeklarationen: Der Fehler wird schon vor der Ausführung gemeldet;
    • [Expected 2 arguments. Found 1.]: Die Anzahl der aktuellen Parameter entspricht nicht der Definition der Funktion.

    Fährt man mit der Maus über einen Funktionsnamen, werden seine Signatur (Parameter, Typen, Rückgabewert) und seine Dokumentation angezeigt, auch für die vordefinierten Funktionen von PHP. Damit [Intelephense] die jüngsten Neuerungen der Sprache kennt, prüfen Sie die Einstellungen von [VS Code] (Menü [File > Preferences > Settings], Suche nach „intelephense php version“) und stellen Sie sicher, dass als PHP-Version 8.5 angegeben ist. Beim Erlernen der Sprache ist es ratsam, alle gemeldeten Warnungen zu beheben. Das ist eine hervorragende Lernmethode.

    [Intelephense] kann eine Datei außerdem formatieren (Rechtsklick, [Format Document]) – gemäß den Codierempfehlungen von [PSR-12]. Die PSR (PHP Standard Recommendations) sind Richtlinien zur Erstellung von Standardcode, die die Interoperabilität und die Wartung von Code erleichtern, der von verschiedenen Personen geschrieben wurde. Sie werden von der [PHP-FIG] auf der Website www.php-fig.org veröffentlicht. Die Empfehlungen [PSR-1] und [PSR-12] legen die Regeln für das Schreiben von Code fest. Hier die Regeln aus [PSR-1]:

    Element
    Regel
    Klassenkonstanten
    Klassenkonstanten MÜSSEN in Großbuchstaben mit dem Zeichen _ als Trennzeichen geschrieben werden.
    Beispiel: [const VAT_RATE]
    Methoden
    Methodennamen MÜSSEN in camelCase geschrieben werden.
    Beispiel: [public function executeBatchTaxes()]
    Eigenschaften
    Eigenschaftsnamen SOLLTEN innerhalb einer Codebasis einheitlich als StudlyCaps, camelCase oder under_score geschrieben werden.
    Beispiele: [$AnnualSalary], [$annualSalary], [$annual_salary]
    Nebeneffekte
    Eine Datei SOLLTE entweder neue Symbole (Klassen, Funktionen, Konstanten usw.) ohne Nebeneffekte deklarieren oder Code mit Nebeneffekten ausführen, aber NICHT beides tun.
    Typen
    Typnamen (Klassen, Schnittstellen usw.) MÜSSEN in StudlyCaps geschrieben werden. Jeder Typ befindet sich in einer eigenen Datei und in einem Namespace mit mindestens einer Ebene.
    Beispiel: [class ScholarshipStudent]

    Die Regel zu den Nebeneffekten besagt, dass eine Datei Folgendes enthalten muss:

    • entweder Deklarationen von Typen (Klassen, Schnittstellen), Funktionen oder Konstanten;
    • oder ausführbaren Code ohne Deklarationen neuer Typen.

    Der Einfachheit halber befolgen die Beispiele dieses Kapitels diese Regel nicht: Jedes Skript ist eine einzelne Datei, die ihre Funktionen definiert und verwendet. Den Code auf mehrere Dateien aufzuteilen, wäre für einfache Beispiele zu umständlich. Bei der Anwendung, die den roten Faden dieses Dokuments bildet, bemühen wir uns, diese Empfehlungen so genau wie möglich einzuhalten, sobald sie mit Klassen geschrieben ist.

$square = function (int $x): int {

};

});

// --------------------------------------------------------------------------
function displayInfo(array $dict, string $key): void
{
    // zeigt den dem Schlüssel zugeordneten Wert im Dictionary $dict an, falls er existiert
    if (isset($dict[$key])) {
        // Wert existiert - ist es ein Array?
        $value = $dict[$key];
        if (is_array($value)) {
            print "[$key," . implode(":", $value) . "]\n";
        } else {
            // $value ist kein Array
            print "[$key,$value]\n";
        }
    } else {
        // $key ist kein Schlüssel des Dictionarys $dict
        print "the key [$key] does not exist\n";
    }
}

// --------------------------------------------------------------------------
function cutNewLineChar(string $line): string
{
    // wir entfernen das Zeilenende-Zeichen aus $line, falls vorhanden
    // (\n unter Unix, \r\n unter Windows)
    return rtrim($line, "\r\n");
