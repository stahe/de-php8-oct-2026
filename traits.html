    9. Traits

    Traits sind Strukturen, die Klassen ähneln. Sie können jedoch nicht instanziiert werden: Sie sind dazu bestimmt, in Klassen eingebunden zu werden. Das Einbinden eines Traits in eine Klasse hat dieselbe Wirkung, als wäre der Code des Traits in die Klasse kopiert worden. Code, der in mehreren Klassen wiederverwendet werden kann, wird in einem Trait abgelegt.

    Traits gibt es seit PHP 5.4. PHP 8 hat mehrere Neuerungen eingeführt, die wir am Ende dieses Kapitels besprechen: die Signaturprüfung für abstrakte Methoden (PHP 8.0), Trait-Konstanten (PHP 8.2) und das Attribut [#[\Override]], das in einem Trait verwendet werden kann (PHP 8.3).

    <?php

declare(strict_types=1);

class Class04
{
    // Konstruktor mit Promotion des Attributs [name]
    public function __construct(private string $name)
    {
    }

    // Getter und Setter
    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $this->name = $name;
    }
}

trait Trait04
{
    // Attribut
    private string $name;

    // Getter und Setter
    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $this->name = $name;
    }
}

class Class05
{
    // Einbindung des Traits
    use Trait04;

    // Konstruktor
    public function __construct(string $name)
    {
        $this->name = $name;
    }
}

// Test --------------
$class04 = new Class04("Tim");
$class05 = new Class05("Burton");
print $class04->getName() . "\n";
print $class05->getName() . "\n";
// Anzeige der beiden Objekte
print_r($class04);
print_r($class05);

    Code-Kommentare

    • Zeilen 5–22: Definition der Klasse [Class04] mit einem Attribut [$name] (vom Konstruktor initialisiert), seinem Getter und seinem Setter;
    • Zeilen 24–39: Wir nehmen den Code von [Class04] – ohne ihren Konstruktor – und verschieben ihn in den Trait [Trait04]. Diesmal wird das Attribut explizit zusammen mit seinem Typ deklariert. Den Konstruktor nehmen wir nicht auf, da ein Trait nicht instanziiert werden kann;
    • Zeile 24: Das Schlüsselwort [trait] kennzeichnet [Trait04] als Trait und nicht als Klasse;
    • Zeilen 41–51: Wir definieren eine Klasse [Class05] , die den Code des Traits [Trait04] einbindet und um einen Konstruktor ergänzt, damit die Klasse instanziierbar ist;
    • Zeile 44: Das Schlüsselwort [use] erlaubt es, innerhalb einer Klasse einen Trait in diese Klasse einzubinden. Es darf nicht mit der Anweisung [use] verwechselt werden, die außerhalb jeder Klasse steht und einen Namen aus einem Namespace importiert;
    • Zeilen 54–60: Tests zeigen, dass die Klassen [Class04] und [Class05] gleich funktionieren.

    <?php

declare(strict_types=1);

trait Trait01
{
    // Attribut
    private int $id = 0;

    // Methode
    public function doSomething(): void
    {
        print "Trait01::doSomething... ($this->id)\n";
    }
}

class Class02
{
    // Einbindung von Trait01
    use Trait01 {
        // die Methode [Trait01::doSomething] ist in der Klasse
        // unter dem Namen [doSomethingInTrait] zugänglich
        Trait01::doSomething as doSomethingInTrait;
    }

    // klassenspezifische Methode
    public function doSomething(): void
    {
        // Attribut id
        $this->id += 10;
        // Verwendung der Methode von Trait01
        $this->doSomethingInTrait();
        // lokale Anzeige
        print "Class02->doSomething\n";
    }
}

class Class03
{
    // Einbindung von Trait01
    use Trait01;

    // lokale Methode der Klasse
    public function doSomethingElse(): void
    {
        // Attribut id
        $this->id += 10;
        // Verwendung der Methode von Trait01
        $this->doSomething();
        // lokale Anzeige
        print "Class03->doSomethingElse\n";
    }
}

// test01 ----------------
function test01(): void
{
    $class02 = new Class02();
    $class03 = new Class03();
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test01
print "test01-----------------\n";
test01();

    Kommentare

    • Zeilen 5–15: ein Trait, der ein Attribut [$id] und eine Methode [doSomething] definiert;
    • Der Trait [Trait01] wird in zwei Klassen eingebunden: [Class02] (Zeilen 17–36) und [Class03] (Zeilen 38–53);
    • Zeilen 20–24: Einbindung von [Trait01] in [Class02]. Auf die Einbindung folgt ein Block [{...}], mit dem sich die eingebundenen Methoden anpassen lassen;
    • Zeile 23: Diese Zeile löst einen Konflikt auf: [Trait01] und [Class02] haben beide eine Methode namens [doSomething]. In diesem Fall hat die Methode der Klasse Vorrang: Die Methode des Traits wird verdeckt. Der Operator [as] macht die Methode [Trait01::doSomething] in der Klasse unter dem Namen [doSomethingInTrait] zugänglich. Innerhalb von [Class02] gelten somit die folgenden Schreibweisen:
      • [doSomethingInTrait] um die Methode [Trait01::doSomething] aufzurufen;
      • [doSomething] um die Methode [Class02::doSomething] aufzurufen;
    • Zeilen 30–32: Die Klasse [Class02] verwendet das Attribut und die Methode von [Trait01] , als wären es ihre eigenen;
    • Zeilen 38–53: Die Klasse [Class03] ist analog zur Klasse [Class02]. Die Einbindung von [Trait01] ist hier einfacher, da es keinen Konflikt zwischen den Methoden von [Trait01] und [Class03] gibt.

    <?php

declare(strict_types=1);

// Klasse, die den Trait ersetzt
class Class01
{
    // Attribut
    private int $id = 0;

    // Setter
    public function setId(int $id): void
    {
        $this->id = $id;
    }

    // Getter
    public function getId(): int
    {
        return $this->id;
    }

    // Methode
    public function doSomething(): void
    {
        print "Class01::doSomething... ($this->id)\n";
    }
}

class Class02
{
    // eine Referenz auf eine Instanz von Class01, die vom Konstruktor injiziert wird
    public function __construct(private readonly Class01 $class01)
    {
    }

    // klassenspezifische Methode
    public function doSomething(): void
    {
        // Änderung des Attributs von Class01
        $id = $this->class01->getId();
        $id += 10;
        $this->class01->setId($id);
        // Verwendung der Methode von Class01
        $this->class01->doSomething();
        // lokale Anzeige
        print "Class02->doSomething\n";
    }
}

class Class03
{
    // eine Referenz auf eine Instanz von Class01, die vom Konstruktor injiziert wird
    public function __construct(private readonly Class01 $class01)
    {
    }

    // lokale Methode der Klasse
    public function doSomethingElse(): void
    {
        // Änderung des Attributs von Class01
        $id = $this->class01->getId();
        $id += 10;
        $this->class01->setId($id);
        // Verwendung der Methode von Class01
        $this->class01->doSomething();
        // lokale Anzeige
        print "Class03->doSomethingElse\n";
    }
}

// test01 ----------------
function test01(): void
{
    // zwei Objekte, die auf zwei verschiedene Instanzen von [Class01] zugreifen
    $class02 = new Class02(new Class01());
    $class03 = new Class03(new Class01());
    // Prüfung
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test02 ----------------
function test02(): void
{
    // gemeinsam genutzte Instanz von [Class01]
    $class01 = new Class01();
    // zwei Objekte, die auf dieselbe Instanz von [Class01] zugreifen
    $class02 = new Class02($class01);
    $class03 = new Class03($class01);
    // Prüfung
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test01
print "test01-----------------\n";
test01();
// test02
print "test02-----------------\n";
test02();

    Kommentare

    • Zeilen 6–28: Die Klasse [Class01] ersetzt den Trait [Trait01]. Der Code von [Trait01] wurde in den Code der Klassen [Class02] und [Class03] übernommen. Hier ist das nicht der Fall: Eine Referenz auf ein Objekt [Class01] wird in die Klassen [Class02] und [Class03] injiziert. Die Attribute der Klasse [Class01] liegen daher außerhalb der Objekte [Class02] und [Class03] . Da das Attribut [$id] privat ist, müssen ein Getter und ein Setter bereitgestellt werden. Das ist der erste Unterschied zu einem Trait: Man muss Code schreiben, um auf die privaten Attribute der Klasse zuzugreifen. Wir hätten das Attribut [$id] öffentlich machen können, das ist jedoch nicht empfehlenswert: Mit einem Setter lässt sich der Wert eines Attributs beim Setzen validieren;
    • Zeile 33: Die Referenz auf das Objekt *[Class01] wird dank Parameter-Promotion durch den Konstruktor in *[Class02] injiziert. Der PHP-7-Kurs verwendete einen Setter [setClass01]. Die Injektion über den Konstruktor ist vorzuziehen: Das Objekt [Class02] ist vollständig, sobald es konstruiert ist, und da das Attribut [readonly] ist, kann die Referenz nicht mehr geändert werden;
    • Zeilen 41–45: Bei jeder Verwendung des Codes [Class01] müssen wir über das Attribut [$this->class01] gehen;
    • Zeilen 51–70: Die Klasse [Class03] ist ein Klon der Klasse [Class02], nur dass ihre Methode einen anderen Namen hat;
    • Zeilen 73–81: der erste Test. Dabei werden zwei verschiedene Instanzen der Klasse [Class01] in die Objekte [Class02] und [Class03] injiziert;
    • Zeilen 84–94: Der zweite Test injiziert dieselbe Instanz der Klasse [Class01] in die Objekte [Class02] und [Class03].

    9.4. Methoden in einem Trait bündeln

    Im vorherigen Beispiel enthielt der Trait Attribute und Methoden. Hier betrachten wir den Fall, dass er nur Methoden enthält. Der Trait ähnelt dann einer Auslagerung von Methoden, die in verschiedenen Klassen verwendet werden können. Da der Trait hier keine Attribute hat, betrachten wir den Fall, dass seine Methoden ausschließlich mit den ihnen übergebenen Parametern arbeiten. Zwingend ist das nicht: Ein Trait kann mit einem Attribut [$this->attribute1] arbeiten, ohne dieses Attribut selbst zu besitzen. In diesem Fall ist es Sache der Klassen, die den Trait verwenden, das Attribut [$this->attribute1] bereitzustellen.

    Hat der Trait nur Methoden, die ausschließlich mit den ihnen übergebenen Parametern arbeiten, zeigen wir, dass sich der Trait durch eine Klasse mit denselben, als static deklarierten Methoden ersetzen lässt.

    Wir erhalten tatsächlich dasselbe Ergebnis wie mit dem Trait [Trait01], was zeigt, dass sich seine Verwendung vermeiden lässt. Wir haben festgestellt, dass die Methoden eines Traits mit einem Attribut [$this->attribute1] arbeiten können, auch wenn der Trait dieses Attribut selbst nicht besitzt; es ist dann Sache der Klassen, die den Trait verwenden, es bereitzustellen. Das ist ein exotisches und fragiles Szenario: Besser ist es, das Attribut [$this->attribute1] in den Trait selbst „hochzuziehen“. So ist es zwangsläufig Teil der Attribute der Klasse, die den Trait verwendet. Am Ende des Kapitels sehen wir, dass PHP 8 eine saubere Lösung bietet, um von Klassen, die einen Trait verwenden, etwas zu verlangen: abstrakte Methoden.

    9.5. Mehrfachvererbung mit einem Trait

    In der Literatur liest man häufig, dass Traits Mehrfachvererbung erlauben: die Möglichkeit, dass eine Klasse von mehreren Klassen erbt. Die Sprache C++ unterstützt dieses Merkmal, Java und C# dagegen nicht, da sie nur Einfachvererbung kennen. Wir zeigen, dass die Verwendung eines Traits in einer abgeleiteten Klasse zwar tatsächlich etwas der Mehrfachvererbung Ähnliches ermöglicht, sich dieser Anwendungsfall aber auch mit einfachen Klassen umsetzen lässt.

    9.6. Einen Trait statt einer abstrakten Klasse verwenden

    Der folgende Anwendungsfall ist häufig: Sie erstellen eine recht allgemeine Schnittstelle I, die mehrere Implementierungen hervorbringen kann. Diese Implementierungen teilen sich gemeinsamen Code, unterscheiden sich aber in anderen Methoden. Es gibt zwei Möglichkeiten, diesen Anwendungsfall umzusetzen:

    • Sie erstellen eine abstrakte Klasse C, die den Code enthält, der den abgeleiteten Klassen gemeinsam ist. Die Klasse C implementiert die Schnittstelle I, aber bestimmte Methoden – die in den abgeleiteten Klassen definiert werden müssen – werden in der Klasse C als abstrakt deklariert, die damit selbst abstrakt ist. Anschließend erstellen wir von C abgeleitete Klassen C1 und C2, die jeweils die abstrakten Methoden ihrer Elternklasse C auf ihre eigene Weise implementieren;
    • wir erstellen einen Trait T, der der abstrakten Klasse C der vorherigen Lösung fast gleicht. Dieser Trait implementiert die Schnittstelle I nicht, da das syntaktisch nicht möglich ist. Anschließend erstellen wir die Klassen C1 und C2, die die Schnittstelle I implementieren und den Trait T verwenden. Diesen Klassen bleibt nur noch, die Methoden der Schnittstelle I zu implementieren, die der von ihnen importierte Trait T nicht implementiert.

declare(strict_types=1);

// ein Trait, das etwas von den Klassen verlangt, die es verwenden
trait CounterTrait
{
    // Trait-Konstante (PHP 8.2)
    public const int STEP = 10;

    // statisches Attribut: jede verwendende Klasse hat ihr eigenes
    private static int $nbInstances = 0;

    // Instanzattribut
    private int $counter = 0;

    // statische Trait-Methode
    public static function getNbInstances(): int
    {
        return self::$nbInstances;
    }

    // abstrakte Methode: die verwendende Klasse muss sie definieren (Signatur seit PHP 8.0 geprüft)
    abstract protected function getName(): string;

    // wird vom Konstruktor der verwendenden Klasse aufgerufen
    private function register(): void
    {
        self::$nbInstances++;
    }

    // konkrete Methode, die die abstrakte Methode und die Konstante verwendet
    public function increment(): static
    {
        $this->counter += self::STEP;
        print "{$this->getName()}: counter=$this->counter\n";
        return $this;
    }
}

class Car
{
    use CounterTrait;

    public function __construct(private string $registration)
    {
        $this->register();
    }

    // Implementierung der abstrakten Methode des Traits
    #[\Override]
    protected function getName(): string
    {
        return "Car[$this->registration]";
    }
}

class Bike
{
    use CounterTrait;

    public function __construct()
    {
        $this->register();
    }

    #[\Override]
    protected function getName(): string
    {
        return "Bike";
    }
}

// Tests
(new Car("AB-123-CD"))->increment()->increment();
new Car("EF-456-GH");
(new Bike())->increment();
// jede Klasse hat ihr eigenes statisches Attribut
print "number of cars: " . Car::getNbInstances() . "\n";
print "number of bikes: " . Bike::getNbInstances() . "\n";
// die Trait-Konstante ist über die Klasse zugänglich, nicht über das Trait
print "step: " . Car::STEP . "\n";
try {
    print CounterTrait::STEP . "\n";
} catch (\Error $ex) {
    print $ex::class . ": " . $ex->getMessage() . "\n";
}

    Kommentare

    • Zeile 9: Seit PHP 8.2 kann ein Trait Konstanten deklarieren. Diese werden zu Konstanten der Klasse, die den Trait verwendet;
    • Zeile 12: Ein Trait kann statische Attribute deklarieren. Wie Instanzattribute werden sie in jede Klasse kopiert, die den Trait verwendet: Jede Klasse hat ihren eigenen Instanzzähler;
    • Zeilen 18–21: Ein Trait kann statische Methoden deklarieren. Im Code des Traits bezeichnet [self] die Klasse, die den Trait verwendet;
    • Zeile 24: Ein Trait kann abstrakte Methoden deklarieren. Jede Klasse, die den Trait verwendet, muss sie implementieren; andernfalls muss sie selbst als abstrakt deklariert werden (siehe die am Ende des Skripts auskommentierte Klasse [Plane] ). Seit PHP 8.0 wird die Signatur der Implementierung (Parameter- und Rückgabetypen) überprüft. So stellt man ordnungsgemäß Anforderungen an die Klassen, die den Trait verwenden, statt vorauszusetzen, dass sie ein bestimmtes Attribut oder eine bestimmte Methode besitzen;
    • Zeilen 33–38: Eine konkrete Methode [increment], die die abstrakte Methode [getName] und die Konstante [STEP] verwendet. Sie gibt [$this] (Typ [static]) zurück, damit sie verkettet werden kann;
    • Zeilen 41–56: Die Klasse [Car] verwendet den Trait, ruft in ihrem Konstruktor die private Methode [register] des Traits auf und implementiert die abstrakte Methode [getName]. Beachten Sie das Attribut [#[\Override]] an dieser Implementierung: Es wird akzeptiert, weil die Klasse eine abstrakte Methode des Traits implementiert;
    • Zeilen 58–72: Die Klasse *[Bike]* tut dasselbe;
    • Zeilen 79–80: Jede Klasse hat ihr eigenes statisches Attribut [$nbInstances];
    • Zeile 82: Die Konstante des Traits ist über die Klasse zugänglich, die ihn verwendet;

    9.8. Fazit

    Aus den vorherigen Beispielen geht hervor, dass Anwendungsfälle, in denen die Verwendung eines Traits einen klaren Nutzen bringt, nicht offensichtlich sind. In unseren Beispielen können wir stets auf ihn verzichten, indem wir ihn durch eine Klasse ersetzen. Nützlich ist er jedoch, um Code über verschiedene Klassen hinweg auszulagern, als gehörte dieser Code zu einer Elternklasse, ohne die einzige Vererbung zu verbrauchen, die einer PHP-Klasse zur Verfügung steht. Genau das werden wir in Version 4 der Übungsanwendung tun.
